1. Introducción

El objetivo de esta práctica es aprender a trabajar con Git y GitHub utilizando el modelo de trabajo Git Flow. Para ello se ha desarrollado una página web didáctica que muestra diferentes formas de manipular elementos HTML mediante JavaScript.

Durante el proyecto se han creado distintas ramas para simular el trabajo de tres usuarios, desarrollar funcionalidades independientes, integrar los cambios, preparar una versión estable y solucionar un problema mediante un hotfix.

2. Fundamentos teóricos

2.1. ¿Qué es Git?

Git es un sistema de control de versiones distribuido que permite registrar los cambios realizados en los archivos de un proyecto. Facilita recuperar versiones anteriores, comparar modificaciones y trabajar con diferentes ramas.

2.2. ¿Qué es GitHub?

GitHub es una plataforma que permite alojar repositorios Git en Internet. Facilita compartir proyectos, colaborar con otros desarrolladores y mantener una copia remota del código.

2.3. Conceptos principales de Git

  • Repositorio: almacena los archivos y el historial del proyecto.
  • Commit: registra un conjunto de cambios.
  • Rama: permite trabajar de forma independiente.
  • Merge: integra los cambios de una rama en otra.
  • Tag: identifica una versión concreta del proyecto.
  • Push: envía los cambios al repositorio remoto.
  • Pull: obtiene e integra cambios del repositorio remoto.
  • Clone: descarga una copia del repositorio.

2.4. ¿Qué es Git Flow?

Git Flow es un modelo de organización del trabajo con ramas Git. Establece diferentes ramas según la finalidad de cada tarea, facilitando el desarrollo paralelo y la preparación de versiones.

  • main: contiene las versiones estables del proyecto.
  • develop: reúne las nuevas funcionalidades antes de publicarlas.
  • feature: se utiliza para desarrollar funcionalidades concretas.
  • release: prepara una nueva versión estable.
  • hotfix: permite corregir errores urgentes de una versión publicada.

2.5. ¿Por qué utilizar Git Flow?

Este modelo permite organizar mejor el desarrollo, separar las funcionalidades, evitar modificaciones directas sobre la versión estable y facilitar la colaboración entre varios desarrolladores. También permite identificar las versiones mediante etiquetas y corregir errores sin interrumpir el desarrollo de nuevas funciones.

3. Creación del repositorio y estructura inicial

Se ha utilizado el repositorio de GitHub curso-javascript-gitflow.

Se creó un README inicial y posteriormente se estableció la rama develop para organizar el desarrollo de las funcionalidades.

La estructura del proyecto es la siguiente:

curso-javascript-gitflow/
├── README.md
├── index.html
├── css/
│   └── estilos.css

    └── app.js

Comandos utilizados

git clone https://github.com/OPC-sys/curso-javascript-gitflow.git
git switch -c develop

Para simular tres usuarios diferentes se modificó el nombre de usuario de Git antes de realizar los commits correspondientes.

4. Desarrollo de funcionalidades

4.1. Usuario 1: estructura inicial

Se creó la estructura HTML de la página, incluyendo una cabecera, un menú de navegación, el contenido principal y un pie de página. También se prepararon los archivos CSS y JavaScript.

Se registró el trabajo mediante el commit: 5e5e48c.

4.2. Usuario 2: feature/contenidoHTML

Se creó una rama independiente para desarrollar la modificación del contenido de los elementos HTML mediante JavaScript.

Se utilizó la propiedad textContent para cambiar el texto de un elemento y restaurar posteriormente su contenido original.

Una vez terminada la funcionalidad, se integró en develop mediante un merge.

Commits principales: 6942db9 y 2567945.

ESPACIO PARA CAPTURA: feature contenidoHTML y su funcionamiento.

4.3. Usuario 2: feature/atributosHTML

Se desarrolló una segunda funcionalidad para modificar los atributos de una imagen HTML mediante JavaScript.

Se utilizó el método setAttribute() para cambiar atributos como src, alt y title. También se añadió la posibilidad de restaurar los valores originales.

La funcionalidad se desarrolló en su propia rama y posteriormente se integró en develop.

Commits principales: b7f62b7 y ccabc12.

ESPACIO PARA CAPTURA: feature atributosHTML y su funcionamiento.

4.4. Usuario 3: feature/estilosCSS

Se creó una tercera rama para trabajar con los estilos CSS desde JavaScript.

Se modificaron propiedades de estilo de los elementos mediante la propiedad style, permitiendo cambiar su apariencia y restaurar los estilos originales.

El código JavaScript incluye comentarios para facilitar la comprensión de las funciones.

Commits principales: 782efa0 y 7045731.

ESPACIO PARA CAPTURA: feature estilosCSS y su funcionamiento.

5. Preparación de la versión 1.0

Después de desarrollar e integrar las tres funcionalidades en develop, se creó la rama release/1.0 para preparar la primera versión del proyecto.

En esta rama se actualizó el README con información de la versión y se creó la etiqueta anotada v1.0.

Comandos utilizados:

git switch develop
git switch -c release/1.0
git add README.md
git commit -m "release(usuario-3): preparar versión 1.0"
git tag -a v1.0 -m "Versión 1.0"
git switch main
git merge --no-ff release/1.0
git switch develop
git merge --no-ff release/1.0

La release se integró tanto en main como en develop. El commit de preparación de la versión fue 7c4af6a.

ESPACIO PARA CAPTURA: rama release y etiqueta v1.0.

6. Corrección urgente: hotfix

Se creó la rama hotfix/mejora-bienvenida a partir de main para corregir el texto de bienvenida de la página.

Se sustituyó el texto «Bienvenido al curso» por «Bienvenido al curso de JavaScript».

El cambio se registró con el commit:

fix(usuario-1): mejorar el texto de bienvenida

Después, la corrección se integró tanto en main como en develop. Finalmente, se creó la etiqueta anotada v1.0.1 para identificar la versión corregida. 

git switch main
git merge --no-ff hotfix/mejora-bienvenida
git tag -a v1.0.1 -m "Corrección de la versión 1.0"
git switch develop
git merge --no-ff hotfix/mejora-bienvenida

El commit de la corrección es 0f3f1c1 y el merge del hotfix en main es 5815509.

ESPACIO PARA CAPTURA: cambio de bienvenida y etiqueta v1.0.1.

7. Conclusiones

Con esta práctica se ha aprendido a utilizar Git y GitHub para gestionar un proyecto de desarrollo web mediante ramas.

Se han creado funcionalidades independientes, integrado cambios mediante merge, preparado una versión estable con una release y corregido un error mediante un hotfix.

También se ha comprobado la importancia de mantener un historial organizado, utilizar commits descriptivos y separar el desarrollo de las versiones estables.

Git Flow facilita la organización del trabajo y permite simular un entorno de colaboración entre varios desarrolladores.
